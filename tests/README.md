# Tests

All test media is synthetic and generated by the scripts in this folder. Nothing in `tests/media/`, `tests/out*/`,
`tests/_smoke/`, `tests/_gui/`, `tests/_cancel/` or `tests/compat_out/` is committed; it is all regenerated.

## Prerequisites

- Windows 10/11 (the GUI tests and the drag-and-drop test use Win32 APIs; the CLI tests also run elsewhere).
- Python 3.11+ with Tkinter (python.org installer).
- A **full** FFmpeg build on `PATH` (`ffmpeg` and `ffprobe` 8.x; the samples need libx264, libx265, libsvtav1, libvpx,
  libopus, libvorbis, libtheora, libspeex and libmp3lame; the gyan.dev "full" build has them all). The sample generators
  and the independent checkers (`e2e_check.py`, `export_audio_test.py`) call `ffmpeg` / `ffprobe` from `PATH`.
- The FFmpeg that ships with the program (the slim build, see "FFmpeg" in the main README) for the conversions
  themselves: set `MKV2MP4_FFMPEG_DIR` to its `bin` folder for the source tests (the tool looks in `bin\` next to the
  program first, then `MKV2MP4_FFMPEG_DIR`, then `PATH`); the exe tests use the bundled `bin\` automatically. Every
  test runner prints the line `ffmpeg used by the tool: <path> | <version> | slim/full`, taken from the tool's own
  lookup (`tests/tool_ffmpeg.py`); the exe writes the ffmpeg it located into its test log (`ffmpeg:<path>`).
- Optional: Pillow (`pip install pillow`) for the window screenshots taken by `gui_test.py`, and for regenerating the
  icon if `assets/app.ico` is ever deleted.

Run everything from the repository root.

## 1. Generate the samples (in this order)

```
python tests/make_samples.py        # tests/media/*.mkv (multi-track, rare audio, AV1/VP9/VP8, DVD and PGS subs, truncated, ...)
python tests/make_obs_samples.py    # tests/media/obs/ (OBS-like recordings, fragmented, crashed, hybrid)
python tests/make_fmp4_samples.py   # tests/media/fmp4/ (fragmented MP4, CMAF, DASH segments, truncated)
python tests/compat_test2.py        # tests/media/extra/ (per-codec samples) + rewrites tests/compat_results2.json
python tests/make_fix_samples.py    # tests/out/_gen2/ (mid-sample cuts, crashed plain MP4, corrupt middle)
python tests/make_flv_ts_samples.py # tests/media/flv_ts/ (FLV, enhanced FLV HEVC/AV1, TS, M2TS, cut, late audio, timestamp jump)
                                    # + tests/media/export/ (normal MP4 with 3 AAC, late audio, illegal track titles)
```

`make_samples.py` writes its own small TrueType test font (`tests/media/_src/testfont.ttf`) and attaches it to
`multi.mkv`; no system font is used. `compat_test2.py` and `compat_test.py` are the evidence harnesses behind
`docs/compat-matrix.md`; rerunning them overwrites `tests/compat_results2.json` / `tests/compat_results.json` (step 1 above already does this for
`compat_results2.json`; run `git checkout tests/compat_results2.json` afterwards if you do not want to keep the change).

## 2. Tests that run from source (no build needed)

```
python tests/run_smoke.py           # converts every sample folder into tests/_smoke/, checks the sources are untouched
python tests/e2e_run.py cli         # CLI end-to-end over all samples + tests/out/_gen, deep checks via e2e_check.py
python tests/fix_checks.py          # regression checks: read errors, cancel during verify, name collisions, HDR re-encode, read-only folder
python tests/export_audio_test.py   # --export-audio: names, codecs/containers, hashes, start times (TS: decoded length equals the source track), tags, blank-title fallback, offsets in the report, export-only for normal MP4
python tests/gui_test.py            # GUI in-process (export-audio checkbox on, MKV/fMP4/TS/FLV/normal MP4): screenshots in tests/_gui/; then gui.py with a file argument
python tests/gui_close_test.py      # closing the window while converting cleans up partial files
python tests/e2e_large.py [loops]   # builds a multi-GB file by looping a sample (default 320 loops), then converts it
```

`e2e_run.py cli` prints `ok`/`FAIL` per file and writes `tests/out/e2e_cli.json`; any entry with a non-empty
`issues` list is a failure. `e2e_run.py` creates `tests/out/_gen/` itself (truncated copies) and also picks up the
`make_fix_samples.py` outputs from `tests/out/_gen2/`. You can pass name fragments to run a subset:
`python tests/e2e_run.py cli obs_ trunc`. Delete `tests/out/cli/` before a full run, otherwise the new outputs get a
` (1)` suffix and the checker looks at the old ones. For TS sources the checker compares packets after the same
normalisation the tool uses (`filter_units` / `*_mp4toannexb` / `aac_adtstoasc`), and for TS/FLV it also checks that
every track's start relative to the video is unchanged within one frame; `ts_discontinuity.ts` must explain the
timestamp jump in its report instead of matching the (bogus) source duration.

## 3. Tests that need the built program

Build first with `python build.py` (see the main README); these use `dist/视频转MP4/视频转MP4.exe`. If that
folder is locked (an old copy of the program is still running from it), build and test elsewhere by setting the
environment variable `MKV2MP4_DIST_DIR` to another folder for both `build.py` and these scripts.

```
python tests/e2e_run.py exe         # drags each sample group onto the exe (PATH limited to System32, so the bundled ffmpeg is used)
python tests/gui_smoke.py           # starts the exe with and without a file, takes screenshots
python tests/cancel_and_exe_test.py # cancel test from source; the exe part runs only when the exe exists
```
